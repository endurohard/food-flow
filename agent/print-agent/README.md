# FoodFlow Print Agent — агент печати на точке

Программа, которая печатает кухонные чеки на принтер, стоящий **в локальной
сети заведения**.

## Зачем он нужен

Сервер FoodFlow стоит в дата-центре и адрес принтера `192.168.x.x` ему
недостижим. Раньше kitchen-service пытался открыть TCP-соединение к принтеру
сам, молча уходил в «simulation mode» и **отвечал успехом без бумаги**.

Агент работает наоборот: он сам, исходящими HTTPS-запросами, спрашивает у
сервера «есть задания для моих станций?» и печатает то, что получил. Публичный
IP, проброс портов и VPN на точке не нужны.

Байты ESC/POS формирует **сервер**, агент только пишет их в принтер — формат
чека меняется на сервере сразу для всех точек.

## Что нужно

- компьютер на кухне (мини-ПК, кассовый ПК, Raspberry Pi), который видит
  принтер и имеет выход в интернет;
- Node.js 18+ (либо готовый бинарник — см. «Сборка бинарника»);
- токен агента из админки.

## 1. Создать агента в админке

Админка → **Принтеры** → «Добавить агента» → укажите название (например
«Кухня, основной ПК»).

Токен показывается **один раз** при создании. Сохраните его — повторно
посмотреть нельзя, можно только перевыпустить («Перевыпустить токен», старый
при этом перестаёт работать).

Там же: станции печати. У каждой станции нужно выбрать агента — станция без
агента чеки не получит, админка об этом прямо пишет.

## 2. Установить агента

```bash
# скопировать папку agent/print-agent на компьютер точки
cd print-agent
npm test            # зависимостей нет, тесты на встроенном node --test
```

Файл настроек (создать вручную):

| ОС | Путь по умолчанию |
|---|---|
| Windows | `C:\ProgramData\FoodFlow\print-agent.json` |
| macOS | `~/Library/Application Support/FoodFlow/print-agent.json` |
| Linux | `/etc/foodflow/print-agent.json` |

```json
{
  "serverUrl": "https://ваш-домен",
  "token": "токен-из-админки",
  "pollIntervalMs": 3000,
  "logFile": "/var/log/foodflow-print-agent.log"
}
```

Путь можно переопределить: `--config=/путь/print-agent.json` или переменная
`FOODFLOW_AGENT_CONFIG`. Переменные окружения перекрывают файл —
`FOODFLOW_SERVER_URL`, `FOODFLOW_AGENT_TOKEN`, `FOODFLOW_POLL_INTERVAL_MS`,
`FOODFLOW_AGENT_LOG`.

Запуск:

```bash
node src/index.js
```

При старте агент печатает в консоль, кем подключился и какие станции получил.
`станций: 0` означает, что в админке к агенту не привязан ни один принтер —
печатать нечего.

## 3. Автозапуск

### Linux (systemd)

```bash
sudo cp scripts/foodflow-print-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now foodflow-print-agent
journalctl -u foodflow-print-agent -f
```

### Windows

Самый простой способ без сторонних утилит — задача планировщика «при входе в
систему»:

```powershell
schtasks /Create /TN FoodFlowPrintAgent /SC ONLOGON /RL HIGHEST ^
  /TR "\"C:\Program Files\nodejs\node.exe\" C:\FoodFlow\print-agent\src\index.js"
```

Для работы без входа пользователя в систему — служба через `nssm install
FoodFlowPrintAgent`.

## Типы принтеров

| Тип | Поле в админке | Пример |
|---|---|---|
| `network` | IP адрес и порт | `192.168.31.87:9100` (порт по умолчанию 9100) |
| `usb` | устройство/порт | `/dev/usb/lp0`, `COM3` |
| `system` | имя системного принтера | `XP-80C`, `\\localhost\XP-80C` |
| `bluetooth` | адрес устройства | `00:11:22:33:44:55` |

## Проверка

1. Админка → Принтеры → карточка станции → «🧪 Тест печати».
   Кнопка **ставит задание в очередь** — она не утверждает, что чек вышел.
2. Факт печати виден в журнале печати на той же странице: `Напечатано` ставит
   агент после реальной записи в принтер, `Ошибка` — с текстом причины
   (нет бумаги, принтер недоступен).
3. Кнопка «👁» показывает текст чека, который уехал на принтер.

Если агент «не на связи» — смотрите лог агента: `serverUrl` недоступен,
неверный токен (401, агент не уходит в бесконечный цикл и говорит об этом),
либо агент просто не запущен.

## Сборка бинарника (без Node.js на точке)

```bash
npm run build:win     # dist/foodflow-print-agent.exe
npm run build:linux
npm run build:mac
```

## Безопасность

- Токен уходит в заголовке `Authorization`, не в URL: иначе он попадёт в логи
  прокси целиком.
- В базе хранится только sha256-хеш токена — восстановить его нельзя.
- Токен агента даёт доступ **только** к заданиям печати своего предприятия:
  ни к заказам, ни к пользователям.
