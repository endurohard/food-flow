# Производство полуфабрикатов и закуп

Как в FoodFlow устроен полный цикл: закупили продукты → сварили свой соус →
собрали бургер → списали остатки при продаже.

## Сквозной сценарий «бургер со своим соусом»

### 1. Приёмка продуктов от поставщика

Админка → Склад → **Накладные** → «Новая накладная»: поставщик, склад,
номер, дата. Затем добавить позиции (товар, количество, цена за единицу)
и нажать **«Принять на склад»**.

Что делает приёмка (`POST /api/suppliers/invoices/:id/confirm`), одной транзакцией:

- приходует товар на склад (`inventory_stock`);
- создаёт FIFO-партии с ценой закупки (`inventory_batches`);
- увеличивает долг поставщику (`suppliers.balance`);
- создаёт расход в finance-service.

Повторное подтверждение отклоняется — двойного прихода не будет.

### 2. Техкарта соуса (производственная)

Админка → Меню → **Техкарты** → тип **«Полуфабрикат (производство)»**:

- *Выход*: товар склада «Соус барбекю», количество 5 (кг);
- *Состав*: томаты 3 кг, специи 0.2 кг, сахар 0.5 кг — всё из склада.

Такая техкарта не привязана к блюду меню (`menu_item_id` = NULL,
`output_item_id` = соус). Именно наличие `output_item_id` делает её
производственной — без него она не попадёт в экран производства.

### 3. Выпуск соуса

Админка → Склад → **Производство** → выбрать техкарту, склад, количество.

`POST /api/inventory/production` одной транзакцией:

- списывает ингредиенты по FIFO;
- считает фактическую себестоимость выпуска (`total_cost`, `unit_cost`);
- приходует соус на склад + создаёт партию `PR-xxxxxxxx` с этой себестоимостью;
- ставит `inventory_items.is_produced = true` и обновляет `cost_price`.

Отмена выпуска (`/production/:id/cancel`) проводит обратные проводки.

### 4. Техкарта бургера

Админка → Меню → **Техкарты** → тип **«Блюдо меню»**:

- *Блюдо*: «Бургер классический»;
- *Состав*: котлета 150 г, булка 1 шт, **соус барбекю 30 г** ← свой полуфабрикат.

Соус здесь — обычный товар склада, поэтому вложенность работает без
дополнительных сущностей: и выход техкарты, и ингредиент ссылаются на
`inventory_items`.

### 5. Продажа и списание

При переводе заказа в `completed` / `delivered` order-service вызывает
`POST /api/inventory/deduct-by-order`. Списываются котлета, булка и соус —
каждый по своей FIFO-цене, поэтому себестоимость блюда учитывает
фактическую цену выпуска соуса, а не ноль.

Списание идёт **после** коммита заказа: нехватка остатка не отменяет
оплаченный заказ, а пишется в лог (склад правится вручную).
Идемпотентно по `orderId` — повторный переход статуса не списывает дважды.

## Вложенность любой глубины

Полуфабрикат может входить в полуфабрикат: маринад → соус → бургер.
Ограничений на глубину нет, себестоимость наследуется по цепочке партий.

От зацикливания (соус из бургера, бургер из соуса) защищает проверка
`assertNoCycle` в `techcard.service.ts` — обход графа в ширину при
создании и изменении техкарты. Попытка замкнуть цикл даёт HTTP 400
с понятным текстом.

## Настройки автосписания

order-service, переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AUTO_DEDUCT_STOCK` | `true` | `false` — выключить автосписание (склад ведётся вручную) |
| `INVENTORY_SERVICE_URL` | `http://inventory-service:3006` | адрес inventory-service |
| `INTERNAL_TOKEN` | — | общий секрет сервис-сервисных вызовов; **без него списание не работает** |

Склад выбирается автоматически: активный склад заведения с
`warehouse_type = 'main'`, иначе самый старый активный.

## Ключевые эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/tech-cards` | список и создание техкарт (блюд и производственных) |
| GET | `/api/tech-cards/:id/cost` | расчёт себестоимости и маржи |
| PUT/DELETE | `/api/tech-cards/:id` | изменение, мягкое удаление |
| GET/POST | `/api/inventory/production` | выпуски и запуск производства |
| POST | `/api/inventory/production/:id/cancel` | отмена выпуска |
| POST | `/api/inventory/deduct-by-order` | списание по техкартам (internal-token или менеджер) |
| POST | `/api/suppliers/invoices` | создать накладную |
| POST | `/api/suppliers/invoices/:id/items` | добавить позицию |
| POST | `/api/suppliers/invoices/:id/confirm` | приёмка на склад |
| GET | `/api/inventory/batches` | FIFO-партии с себестоимостью |
| GET | `/api/inventory/items/:id/cost-history` | история себестоимости |

## Чего пока нет

- Инвентаризация (сверка факт/учёт с актом расхождений).
- Списание порчи с причиной — есть только общий `write_off` в движениях.
- Перемещение между складами в UI (`movementType: 'transfer'` в API есть).
- Себестоимость в техкарте считается по текущему `cost_price` товара,
  а не по средневзвешенной за период — для расчёта маржи это приближение.
